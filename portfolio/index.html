01. 이미지 생성 모델을 직접 학습시켜 게임 리소스를 생산

외부 이미지 API에 의존하지 않고, 로컬 GPU에서 학습한 모델과 LLM이 설계한 프롬프트로 카드 일러스트를 대량 생산해 실제 출시 앱에 적용했습니다.

수행한 일
캐릭터 24명의 카드 일러스트 240장(캐릭터 × 슬롯 10개)을 캐릭터 정체성을 유지한 채 장소·의상·포즈가 모두 다르게 생성하고, 검수를 거쳐 게임 리소스로 교체.
방법
  • 학습: 로컬 PC(RTX 4080)에 ComfyUI + SDXL 계열 체크포인트 환경 구축. 승인된 원화만으로 캐릭터별 정체성 LoRA 24개와 공통 스타일 LoRA를 학습. 정체성 캡션(머리·눈·장신구)과 스타일 캡션(선화·채색·배경)을 분리하고, 프레임·UI 단어를 캡션에서 제외해 생성물에 프레임이 섞이는 문제를 원천 차단.
  • 프롬프트 설계: LLM이 슬롯별 장소·의상·포즈 변형 규칙을 설계하고, Python(build_prompts.py)이 캐릭터 간 겹치지 않도록 240개 프롬프트를 JSON으로 생성.
  • 생성: Python(gen_all.py, regenerate_local_v2.py)이 ComfyUI HTTP API에 체크포인트 + 정체성 LoRA + 얼굴 refiner LoRA + IP-Adapter(원화 정체성 참조) 그래프를 캐릭터별 강도로 일괄 큐잉.
  • 자동 검수: audit_final.py가 규격, SHA-256 바이트 중복, dHash 유사 구도, Laplacian 선명도를 검사하고 검수 시트를 생성. 불량·장면 불일치 38장은 GPT 이미지 모델로 재생성하는 하이브리드 운영.
  • 적용·검증: apply_final.py가 24×10 슬롯 manifest를 검증한 뒤 Unity 리소스 경로와 GUID를 보존해 교체. 임포트 240장 PASS, Console 에러 0. 학습에 쓰지 않은 프롬프트 20개로 시드 고정 A/B 블라인드 비교를 통과할 때만 운영 LoRA를 교체하는 게이트 운영.
결과
실제 출시 앱에 적용 완료. Star Guardians (Google Play · App Store 공개) 카드 일러스트 240장 전면 교체, 학습 데이터·파라미터·체크포인트/LoRA 해시·검증 시트를 보관해 재현 가능한 상태로 유지. Python 스크립트 약 1,600줄.

02. 역할별 에이전트를 정의한 오케스트레이션 체계로 1인 개발

"AI에게 무엇을 맡기고 무엇은 사람이 검수하는가"를 코드와 문서로 강제해, 혼자서도 여러 프로젝트를 병행 출시할 수 있는 구조를 만들었습니다.

수행한 일
프로젝트에 종속되지 않는 전역 오케스트레이션 구성을 Python으로 구축하고, 기획·코딩·리뷰·테스트·3D·에디터 조작을 역할별 에이전트에 분배해 게임 5종을 기획부터 스토어 출시까지 1인으로 완료.
방법
  • 역할 정의: roles.json에 explorer · log-triage · tester(저비용/low, read-only) · code-worker · unity-worker · blender-worker(중간/medium, workspace-write) · reviewer(상위/high, read-only) · Claude 계열 reviewer/architect(도구 없는 텍스트 검토)를 모델 등급·reasoning effort·샌드박스 권한별로 정의.
  • 호출 규격: ask_claude.py가 GOAL/CONTEXT/FILES/CONSTRAINTS/ACCEPTANCE 패킷의 필수 항목을 검증하고 64KB를 넘으면 거부, 티어(cheap/normal/strong/architect)별로 모델 라우팅, 호출 증적을 JSONL로 기록. 출력은 STATUS/FINDINGS/CHANGED/ERRORS/NEXT로 통일.
  • 안전 규칙: AGENTS.md / CLAUDE.md에 파괴적 Git·자산 삭제 금지, 변경 불가 식별자(패키지명·Firebase·AdMob) 목록, 파일당 단일 소유자, 스크린샷 같은 고비용 검증의 사용 기준을 명문화. 워커·검증·복구 스크립트(codex_worker.py, validate.py, restore.py)로 실패 시 되돌릴 수 있게 구성.
  • 검수 게이트: 생성 단계(이미지→애니메이션→스프라이트)마다 사람 승인, 게임별 검수 정책(전수 검사 대상과 대표 케이스만 볼 대상 구분), 세션 인계 문서로 상태·근거·다음 작업 보존.
  • 실패의 자산화: 첫 출시에서 겪은 키스토어 분실·AdMob ID 변경 재심사·iOS ATT 누락을 원인·영향·예방 체크리스트로 정리한 릴리즈 플레이북을 이후 모든 프로젝트의 필수 절차로 적용.
결과
약 1년 동안 모바일 게임 4종과 PC 게임 1종 출시. 첫 출시 이후 재심사 사고 재발 0건, 에이전트 교체·세션 단절 시에도 작업 연속성 유지.

03. MCP로 에이전트가 엔진·3D 툴·IDE·DB를 직접 조작하게 연동

에이전트가 코드 텍스트만 내놓는 단계를 넘어, 도구를 직접 실행하고 결과를 스스로 확인하게 만들었습니다.

수행한 일
Unity MCP, Blender MCP, 이미지 생성 MCP, 브라우저 MCP를 오케스트레이터에 연결하고, 워크스페이스 오바인딩을 막는 Python MCP 래퍼를 작성.
방법
  • unity_mcp.py: 현재 작업 디렉터리에서 Unity 프로젝트 루트(ProjectSettings/Packages)를 탐지해 그 프로젝트에만 MCP를 바인딩. Unity 프로젝트가 아니면 에디터 조작을 노출하지 않아 다른 프로젝트에 잘못 붙는 사고를 방지.
  • Unity MCP로 씬 구성·스크립트 작성·테스트 실행·에디터 검수, Blender MCP로 파츠 모델링·리깅·렌더, 이미지 생성 MCP로 스프라이트 시트 생성, 브라우저 MCP로 스토어 콘솔·심사 상태 확인을 에이전트에 위임.
  • MCP 버전을 고정(예: Unity MCP 10.1.x)하고 생성물 정리 규칙을 문서화해 도구 업데이트로 인한 회귀를 통제.
결과
모빌리티 메이커의 3D 파츠 에셋과 Snackcade·Star Guardians의 씬·UI 작업 상당 부분을 에이전트가 직접 수행, 결과물은 모두 출시 빌드에 포함.

04. 같은 방식을 회사 인사 시스템에 적용

개인 프로젝트에서 검증한 에이전트·MCP 방식을 사내 업무 시스템 개발에 그대로 옮겼습니다. (팬택씨앤아이 플랫폼개발팀, 2025.03~ 재직 중)

수행한 일
출퇴근·근태 신청, 개인정보 변경 신청 등 임직원 셀프서비스 기능을 인사 시스템 모바일 앱으로 신규 개발(2026.06~). 기존 인사 시스템 유지보수 일부에도 같은 방식 적용.
방법
  • IntelliJ MCP + Oracle DB MCP를 에이전트에 연결해, AI가 실제 코드베이스와 DB 스키마·데이터를 읽고 쿼리를 검증한 뒤 코드를 작성하는 파이프라인 구성. 스키마 변경이 코드에 반영되지 않아 생기던 오류를 사전에 차단.
  • 인사 도메인 규칙(근태·신청/승인 흐름·개인정보 변경)을 에이전트 지시서로 정리해 반복 CRUD·검증 로직 생성을 AI에 위임. 설계·데이터 정합성·권한 검토는 사람이 담당하고 결과는 코드 리뷰와 자동 테스트로 검증.
결과
모바일 앱 개발 완료 후 현재 App Store 심사 진행 중. 화면·API 단위 개발 리드타임 단축.
